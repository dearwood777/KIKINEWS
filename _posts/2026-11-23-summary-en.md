### [GLM‑5.4: First Loop Transformer Architecture](https://z.ai/blog/glm-5.4) ⭐️ 8.0/10

Zhipu AI’s GLM‑5.4 is the first model to use a loop transformer architecture, replacing the standard transformer’s unrolled attention and feed‑forward layers with a single weight set that is reused across token positions. The change reduces memory‑bandwidth bottlenecks and improves coding‑related inference, and the model is available only through Z.ai’s new Coding Plan.

hackernews · foohis · Nov 23, 10:06 · [Discussion](https://news.ycombinator.com/item?id=50609685)

**「Loop Transformer Basics」** A loop transformer reuses a single transformer block multiple times, applying the same weights across several passes to simulate a deeper network while keeping the parameter count low. This weight‑tied depth‑unrolling lets models like Z.ai’s GLM‑5.4 achieve reasoning depth comparable to 2–3 T‑parameter models without adding parameters, as the shared block is run repeatedly during inference.

**「Impact」** Developers who want to use GLM‑5.4 must subscribe to the Coding Plan, as the model is not yet exposed via OpenRouter or the standard Z.ai API, limiting immediate access for existing users.

**「Community Discussion」** Commenters note that the loop transformer design is a promising direction for reducing memory traffic and praise Zhipu’s transparency, but also point out that the model’s limited availability and higher latency for simple tasks can be frustrating.
