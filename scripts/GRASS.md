# 报头卡草带（`.kiki-grass`）实现说明

> 位置：`scripts/web_polish.py` 里 `// 12a) 报头卡的两层氛围件` 一节，函数 `buildGrass()` 与 `startGrassWind()`。
> 当前版本：v37（2026-11-23）。用户已验收观感「草地这个问题不大了」，后续只允许微调幅度，不要重构。

## 1. 结构

```
.hero
└── .kiki-grass        position:absolute; left:6px; right:6px; bottom:0; height:9px; overflow:hidden; z-index:1
    └── .kg × N        position:absolute; bottom:0; transform-origin:50% 100%; will-change:transform
        └── svg        100×100 viewBox + preserveAspectRatio:none，transform:scaleX(var(--fl,1))
```

- 每簇 `.kg` 是一整块 100×100 的 SVG 缩小到 `14~18px` 宽、`6.5~10px` 高。
  里面是 1 条草皮 rect（`y=84 h=16`）+ 7 条细叶 path（粗细/深浅交替），底部连成一片草皮，
  叶尖参差 —— 形状是用户比对参考图后认可的，**不要再改形状**。
- 容器 `height:9px` 目前小于最高的簇（10px），会轻度裁顶；若以后要加高，必须同步把容器改高。
- 簇数 `n = clamp(18, 110, round((vw-12)/10))`，竖屏 484px 宽约 47 簇。
- 每簇随机量：`__x`(0~1 位置)、`__ph`(呼吸相位)、`__b`(固定偏斜)、`__amp`(6.2~16)、`__sk`(15~35)、
  `--fl`(一半水平翻转)、`opacity 0.55~0.89`。
- `buildGrass` 记 `g.__vw`，`layoutVine` 发现视口宽变化 >40px 就重铺（否则旋转后按百分比拉散）。

## 2. 风场（`startGrassWind`）

纯 JS，**不用 CSS 关键帧**（关键帧＝固定周期＋固定幅度＋无限往复，被用户判为「一个人原地招手」）。
每帧 50fps 上限（`ts-last<20` 直接 return），逐簇算角度后写 `transform: rotate() skewX()`。

### 2.1 一维 value noise

```
NZ = 96 个 LCG 随机点（seed 20261）
nz(x): a=floor(x), b=a+1, t=x-a, t = smootherstep(t) = t³(6t²-15t+10)
       返回 NZ[a%96]*(1-t) + NZ[b%96]*t
```

**插值必须是 smootherstep 而不是 smoothstep**：smoothstep 的二阶导在格点上是断的，
一格一格接起来会出现「折点」—— 草从左边斜一下突然翻到右边，用户描述的「像墙上开关，啪一下」就是这个。

### 2.2 三分量合成

```
gust = 0.62 + 0.38 * nz(t*0.32 + 4)                    // 阵风包络：整片一起大/小
f1   = nz(__x * 13.0 - t * 2.0)                        // 沿 x 传播的波（成片起伏）
own  = nz(t * 1.5 + __ph * 6.2 + 2)                    // 每簇自己的呼吸（各摇各的）
base = __b                                             // 每簇固定的个人偏斜，不随时间变

s = (f1*0.50 + own*0.36 + base*0.14 - 0.5) * 3.85      // 3.85 = 幅度总增益
s = s / (1 + |s|*0.45)                                 // 软饱和，代替硬 clamp
ang = __amp * (s*0.86 + (nz(t*1.2 + __ph*9 + 30) - 0.5)*0.24) * gust
sk  = __sk * s * 0.80 * gust                           // skew 必须跟着 s 连续过零
```

### 2.3 三个「必须」，缺一个就假

1. **`f1` 的空间频率必须够高（`x*13`）**。`nz` 是格点噪波，`x*3.4` 意味着整条 47 簇只跨
   3.4 格 → 十几簇共享同一个相位 → 整片同时朝一边倒，用户原话「像军队里稍息，一个人挨一个人往同一方向倒」
   （实测一帧 87% 的簇倒向同一边）。`x*13` 约 3 簇换一个峰谷才有「一波接一波推过去」。
2. **`own` 的相位必须与位置无关（`__ph` 随机）**。只靠空间波，相邻簇必然近似同相；
   加了这一项才有「各摇各的」。
3. **`skewX` 必须跟 `s` 同号连续变**。老写法 `|s| * (ang>=0?1:-1)`，`ang` 一过零 skew 就从
   `+20°` 跳到 `-20°`，肉眼就是「啪」。这是「不顺滑」的头号元凶。

### 2.4 禁止的写法（都试过，都被否）

| 写法 | 用户评价 |
|---|---|
| CSS `@keyframes` 固定周期往复 | 「一个人拿胳膊前后招手，机械重复」 |
| 只有很短的噪波、波长 5~6 峰 | 「只有波扫到哪儿才抖一下，整片看着静止」 |
| 长波 3 峰 + 全局 `bias` 顺风偏置 | 「军队稍息，一排人往同一方向倒」 |
| 硬 `clamp(±1)` | 峰值被削成平顶 → 「撞在两端不动」 |

## 3. 实测（v37，竖屏 484×820，47 簇）

- 同帧角度：`sd ≈ 3.9~4.2°`，范围约 `-7° ~ +10°`，正/负簇数接近 45:50
- 相邻簇角度差均值 ≈ `3.4°`（最大 ~10°），连续同向最长 2 簇 → 不再「排队」
- 两帧（0.3s）之间头部角度 `10.3° → 3.9°` 平滑过渡，无跳变
- `window.__kwGrass.frames` 可查帧计数（不可见窗口下 rAF 会被节流，验证流畅度不能只看这个）

## 4. 调参指南

| 想改什么 | 改哪里 |
|---|---|
| 摆得更大/更小 | `s` 的增益 `3.85`（用户口径「稍微大一丝丝」= 每次 ±7% 左右） |
| 摆动更快/更慢 | `f1` 的 `t*2.0`、`own` 的 `t*1.5`、第三项 `t*1.2`（0.5Hz 左右是顺滑档） |
| 起伏更碎/更成片 | `f1` 的 `x*13.0` |
| 各簇差异更大 | `own` 权重 `0.36`（对应从 `f1` 的 `0.50` 里挪） |
| 整片偶尔一起倒 | 加大 `__b` 权重或给 `gust` 加下限，但**不要再加全局时间偏置** |
