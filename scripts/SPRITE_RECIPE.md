# 逐帧动作素材 · 标准做法（可复用配方）

> 适用：网页里要一个"有生命感的小角色/小物件"逐帧动起来，素材靠 AI 图生成，
> 但要保证**尺寸不跳、脚不沉、换动作为不穿帮**。这个配方是从报头小人（葫芦娃）那三轮返工里提炼的，
> 换成任何"AI 出图 → 网页逐帧动画"的活都能直接照做。
> 报头小人的具体实现见 `scripts/WALKER.md`，这里是**通用流程**。

---

## 0. 一句话原则

**同一角色只允许有一套尺度**：所有动作素材都归一到"同一个身高"，代码里只认一个 `PH`（角色高度）。
任何"每帧自己量包围盒自己定位置"的做法，最后都会变成"走到某处突然沉下去 / 忽大忽小"。

## 1. 出图（image_edit）

- **必须喂一张已验收的现有素材当参考图**（走路雪碧图里的一帧、或原画立绘）。
  只说"画一个葫芦娃爬墙"，AI 会给一套新画风 + 新头身比；配上参考图并写明
  "同一角色 / 同一画风 / 同一头身比 / 同样描边与配色"，比例才守得住。
- 一轮出 3～4 个"关键姿势"（不是中间帧）：循环动作只要 首 / 过渡 / 另一侧 / 过渡 就够。
- 提示词里写死约束：
  - **纯白画布，不要画墙、不要画墙的边缘线、不要画投影/阴影纹理**（否则墙线和投影会跟人物连成一片被一起抠进去）；
  - 姿态约束写成"不许出现什么"（例如"手臂绝对不能举到头顶以上"），比只写"要什么"有效；
  - 背景纯白 + 人物不裁切 + 四周留白 + 竖构图居中（方便后续统一裁剪）。
- 出图尺寸别太小（600×900 起），后面要缩放。

## 2. 挑帧

- 只看两件事：**头身比是否一致、姿势语义是否正确**。
- 明显偏小/偏远的帧直接丢（一张坏帧会让整条循环抖一下）。
- 头宽可以量（顶部 20% 行内最大连续游程 ≈ 头宽），但**只用来判断一致性，不用来定尺度**（见第 4 步）。

## 3. 抠底（去白底 + 去投影）

1. 亮度阈值（比如 `亮度 > 196`）得到"疑似背景"，从**四条边**做 flood fill，只去掉连到边界的背景；
2. 只保留**最大连通块**（人物本体），丢掉飘在旁边的墙线/纸屑；
3. 剩余的中亮度 + 低彩度像素（`118 ≤ 亮度 ≤ 212 且 彩度 < 22`）当投影灰线清掉；
   黑描边亮度更低、皮肤/白裤子彩度高或亮度更高，不会被误伤。

## 4. 归一（这一步最容易翻车）

- **裁剪框**：先用 `alpha>30` 的硬掩码再取 bbox。直接用 `alpha.getbbox()` 会把抗锯齿的
  alpha=1..30 算成内容，框底多出几十行空像素 → 底对齐后"脚离格底 26px"，看着就是悬空/沉字。
- **缩放锚点用身高，不用头宽**：AI 图头身比经常比手绘素材大（实测 0.38 vs 0.21），
  按头宽对齐会把人物缩到 55% 高，一换动作人就变小。统一压到和既有素材**同一个身高像素数**。
- **底对齐**：缩放后再量一次内容 bbox，让"有内容的底边"正好压在格底（不是让图片底边压格底）。
- **水平对齐用"头顶最宽的连续段中点"**，不要用 bbox 中线：动作帧的手常向前伸，bbox 中线会偏。
- 格宽取所有帧的最大内容宽度 + 余量，所有帧等宽等高。

## 5. 拼条

- 单行横向雪碧图，每帧等宽格，RGBA 透明底，`optimize=True` 存 PNG；
- 记下 `{格宽, 格高, 帧数, 角色在格内的高度, 角色脚底 = 格底}`；
- 需要镜像时**不要另存一张翻转图**，运行时翻整框（见第 6 步）。

## 6. 接入代码（网页侧）

```js
var C = { w: 150, h: 220, charH: 180, n: 4, url: 'xxx-sheet.png?v=1', fps: 10 };
// 框高 = PH * C.h / C.charH  → 角色正好是 PH 高
// 框 top = PH - cellH        → 框底 = 脚底 = 地形线
// img: position:absolute; left:0; bottom:0; display:block; verticalAlign:top
// 切帧: img.style.transform = 'translateX(-' + i*cellW + 'px)'
// 镜像: box.style.transform = 'scaleX(-1)'   ← 翻整框；翻图会让 translateX 的帧序错位
```

- 素材在脚本解析阶段就开始 `new Image()` 预载，**图没到就先"站住"**（或退回上一套素材），
  绝不能让角色凭空消失。
- 帧索引跟"位移/时间"同一个量推出来（`floor(t*fps)%n`），别用独立计时器——
  两个时钟一定会漂，漂了就是"腿在动、人在滑"。
- 资源带 `?v=` 版本号，换图必 bump（CDN / WebView 缓存很顽固）。

## 7. 自检（交付前必须做，不许"看着差不多"）

1. **DOM 真值**：`img.naturalWidth/naturalHeight`、框的 `getBoundingClientRect()`、
   与地形/墨迹上沿比对（`|脚底 - 地平线| < 1px`）；
2. **逐帧在动**：连续读 `img.style.transform`，应看到 `0 → -x → -2x → …` 的跳变，不变就是静帧；
3. **真有画面**：headless 浏览器截图 + 裁切放大目视（虚拟时间下 rAF 会冻住，只验"这一帧长什么样"）；
4. **等高对照图**：把新素材和既有素材按同身高并排放一张 montage 看一眼，尺寸/画风不一致一眼就能发现。

## 8. 发布

- 脚本和页面**双推**（main + gh-pages）：每日重刷用的是 main 上的脚本，页面走 gh-pages。
- 素材只推 gh-pages 一份，页面引用相对路径。
