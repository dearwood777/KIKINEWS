GLM‑5.4: First Loop Transformer Architecture▍8.0/10

hackernews · foohis · Nov 23, 10:06 · Discussion

Zhipu AI's GLM‑5.4 is the first model to use a loop transformer architecture, replacing the standard transformer's unrolled attention and feed‑forward layers with a single weight set that is reused across token positions. The change reduces memory‑bandwidth bottlenecks and improves coding‑related inference, and the model is available only through Z.ai's new Coding Plan.

Loop Transformer Basics

A loop transformer reuses a single transformer block multiple times, applying the same weights across several passes to simulate a deeper network while keeping the parameter count low. This weight‑tied depth‑unrolling lets models like Z.ai's GLM‑5.4 achieve reasoning depth comparable to 2–3 T‑parameter models without adding parameters, as the shared block is run repeatedly during inference.

Impact

Developers who want to use GLM‑5.4 must subscribe to the Coding Plan, as the model is not yet exposed via OpenRouter or the standard Z.ai API, limiting immediate access for existing users.

Community Discussion

Commenters note that the loop transformer design is a promising direction for reducing memory traffic and praise Zhipu's transparency, but also point out that the model's limited availability and higher latency for simple tasks can be frustrating.

中文

GLM‑5.4：首次循环 Transformer 提升代码生成

Zhipu AI 发布 GLM‑5.4，首次引入循环 Transformer 架构，专为代码生成优化。该模型仅在 Z.ai 的 Coding Plan API 计划下可用，OpenRouter 及常规计划尚未接入。循环 Transformer 通过在一次推理中多次复用同一层权重，显著降低了内存带宽瓶颈，提升了代码生成效率。

循环 Transformer 先前概念

循环 Transformer 是一种参数高效的设计，通过多次重复使用同一 Transformer 块来模拟更深层网络的推理能力。此前已有研究（如 EmergentMind 的文章）阐述了权重共享与递归迭代的实现方式，并在实验中证明其可在保持参数量不变的情况下提升算法推理性能。

影响

使用 Z.ai Coding Plan 的开发者可在推理时获得更快的响应时间，尤其在需要多层权重复用的代码生成任务中。

社区讨论

评论者赞赏 Zhipu 的透明度，并指出循环 Transformer 能解决传统 Transformer 的内存带宽瓶颈；有人提到中文模型在“马拉松思考”模式下仍显慢。
